## 4. Defects found & fixed during baseline (each with repro + root cause)

### 4.1 `build.ps1` VS auto-detection broken with ≥2 VS installs — P0 (build blocker)
- **Repro:** this machine has VS2022 + VS2026 Build Tools; `vswhere -products *`
  returns an array, `$vsJson.installationPath` becomes an array, `Join-Path`
  throws, MSVC env is never imported → `No CMAKE_CXX_COMPILER could be found`.
- **Root cause:** single-install assumption in `Import-MSVCEnvironment`.
- **Fix (user-approved):** prefer `$env:VCVARS` override, else newest 17.x
  (VS2022) install, else newest install. CI (single VS) unchanged.
- **Regression test:** manual — build succeeded on a 2-install machine; CI path
  is functionally identical for one install.

### 4.2 `build.ps1` CRT deploy silently failed — P0 (broken self-containment)
- **Repro:** after build, `[Deploy] MSVC VC14x.CRT not found` despite
  `D:\VS2022BuildTools\VC\Redist\MSVC\14.44.35112\x64\Microsoft.VC143.CRT`
  existing; no vcruntime/msvcp in `bin/`.
- **Root cause:** PowerShell single-element-array gotcha — `$crtRoots` from a
  one-element pipeline is a scalar string, so `+=` concatenated two paths into
  one bogus path (`...\14.44.35112\D:\VS2022BuildTools\...`).
- **Fix:** wrap the candidate list in `@( @(...) )` before `+=`.
- **Verification:** `[Deploy] MSVC CRT <- ...VC143.CRT`; 6 CRT dlls present in `bin/`.

### 4.3 `compare_session_tests` crashed (0xc0000409) — P0 (real product bug)
- **Repro:** `ctest -R compare_session_tests` → `Assertion failed: r->blinkIndex
  == 1 && "blinkIndex must survive round-trip"` at `src/test_compare_session.cpp:87`.
- **Root cause:** nothing in the product drives `CompareEngine`'s
  `BlinkController` — the blink UI (`CompareWorkspace::startBlink/applyBlink`)
  only toggles cell visibility, so `CompareEngine::session()` always captured
  `blinkIndex == -1` and the persisted CompareSession never carried blink state
  (breaks save→close→reopen restore of blink mode — a M15 feature contract).
- **Fix:** `CompareWorkspace::syncEngineBlink()` mirrors the blink target into
  `m_engine.setBlinkIndex(...)` on `startBlink`, and `stopBlink()` calls
  `m_engine.clearBlink()`.
- **Regression test:** existing `compare_session_tests` now passes (it asserts
  the full round-trip including blink).

### 4.4 `bench_enforce` failed on B10 (100 MP viewport 1480 ms > 1000 ms) — P1 (gate contradiction)
- **Repro:** `ctest -R bench_enforce` → `[FAIL] B10 hundred_mp_viewport_ms=1480.79`.
- **Evidence:** this machine is a 2-core Xeon (~2.9–3.8× slower than the
  baseline box across B3/B10/B12); the committed baseline measured B10 = 392.8 ms
  (2026-07-24, faster hardware). All other hard gates passed here.
- **Root cause:** `performance_budget.json` explicitly declares B10
  **report-only** (excluded from `scenario_map`, only ±10% regression-checked),
  but `scenarioHundredMpTiles()` hard-coded an absolute 1000 ms gate in
  `r.passed` — code contradicted its own documented spec and turned a
  report-only scenario into a hard fail on legitimately slower hosts.
- **Fix:** B10 verdict is now structural (viewport filled + warm request served
  from cache). Absolute latency stays available in `r.detail` and is
  regression-checked under `--regression`. **No budget file was edited.**
- **Proposal (recorded, not executed):** if the team wants an absolute B10 cap,
  it must be a data-driven entry in `performance_budget.json` with hardware
  provenance documented — it cannot be a hard-coded constant that fails VMs.

### 4.5 `package_portable.ps1` CRT search hard-coded to `D:/msvc` — P1 (packaging defect)
- **Repro:** packaging warned `MSVC VC14x.CRT not found under D:/msvc`; the
  portable zip lacked vcruntime/msvcp → would fail `0xc0000135` on clean Windows.
- **Fix:** CRT root resolved from `VCToolsRedistDir` → vswhere VS root →
  legacy `D:/msvc`; zip now contains all 6 CRT dlls.
