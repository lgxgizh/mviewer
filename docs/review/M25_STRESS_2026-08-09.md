## List-view finding and fix

The first Release baseline exposed a real List-mode UI stall: 2010.3 ms with
the default scheduler and 2672.9 ms with one worker. `updateVisibleRange()` used
an empty `gridSize()` in List mode; after the dimensions were clamped to 1x1,
the whole 10,000-image directory appeared visible. The UI thread then probed the
thumbnail cache for every path and scheduled the entire directory.

Visible ranges are now computed arithmetically per view mode. List uses wrapped
columns, Details uses vertical fixed-height rows, Filmstrip uses horizontal
cells, and icon modes keep their row-major grid calculation. The corrected
Release results are 335.6 ms and 269.0 ms respectively: about 83% and 90% lower.
`workflow_ux_tests` now guards the behavior by asserting that a 600-item List
first screen schedules a bounded set of unique paths, not the whole directory.
