# M13.3 — Performance Budget Gate (Acceptance)

**Status:** In progress
**Priority:** P0 (user-requested, explicitly ordered #2 in the Product-Beta plan)
**RFC:** `docs/rfc/011-performance-budget.md` (Accepted)
**Update note (2026-08-14):** The original gate was intentionally additive. It
now also updates `build.ps1`, `ci.yml`, and the benchmark CTest registration to
make CPU-aware local execution and uncontended measurements explicit.

## Goal

Turn the existing benchmark harness (`mviewer_bench`) from a *report-only / nightly*
instrument into a **hard CI gate**: a violated budget blocks the PR (the noisier
baseline diff vs `benchmark/perf_baseline.json` stays a nightly trend signal).
Budgets are **data-driven** via `benchmark/performance_budget.json` (single
source of truth), not hardcoded.

## Why now

The review's M13.3 item asked for "Performance Budget Gate → CI 自动检测性能回归".
Prior state (verified from tree):

- `mviewer_bench --enforce` existed and exited non-zero on violation, BUT
  - only 3 budgets were hardcoded (`B2<100ms`, `B8<16ms`, `B9` soak);
  - it ran **only in `nightly.yml` with `|| true`** → never blocked anything;
  - `performance_budget.json` (the user's explicit schema) did not exist.

So the gate was *present in spirit* but **non-binding**. This milestone makes it binding.

## Design

### 1. Data-driven budgets — `benchmark/performance_budget.json`

Current file on `master` (`schema_version: 2`, **14 budgets** mapped to the
scenarios B1–B9 + B11–B15; B0/B10/TRACE stay report-only, B10 is still
±10 % regression-checked under `--regression`):

```json
{
  "schema_version": 2,
  "budgets": {
    "qt_event_loop_probe_ms": 50,
    "first_thumbnail_ms": 100,
    "decode_p50_ms_jpeg": 250,
    "thumbnails_per_sec": 7,
    "cache_hit_ratio": 0.10,
    "peak_cache_bytes": 536870912,
    "switch_warm_p50_ms": 50,
    "image_switch_ms": 16,
    "baseline_return_ok": 1.0,
    "decode_4k_jpeg_ms": 400,
    "decode_8k_ms": 2000,
    "cache_hit_rate": 0.10,
    "first_frame_latency_ms": 120,
    "zoom_frame_ms_b15": 600
  },
  "scenario_map": { "B1":"qt_event_loop_probe_ms",  "B2":"first_thumbnail_ms",
                    "B3":"decode_p50_ms_jpeg",      "B4":"thumbnails_per_sec",
                    "B5":"cache_hit_ratio",         "B6":"peak_cache_bytes",
                    "B7":"switch_warm_p50_ms",      "B8":"image_switch_ms",
                    "B9":"baseline_return_ok",      "B11":"decode_4k_jpeg_ms",
                    "B12":"decode_8k_ms",           "B13":"cache_hit_rate",
                    "B14":"first_frame_latency_ms", "B15":"zoom_frame_ms_b15" },
  "regression": { "baseline_file":"benchmark/perf_baseline.json",
                   "max_regression_pct":10, "fail_on_regression":true }
}
```

`mviewer_bench --enforce --budget <file>` loads every key of `budgets` into
`Budget::limits` and `scenario_map` into `Budget::scenarioMap`, overriding the
in-code defaults — the former hardcoded `100.0`/`16.0` constants are now the
`first_thumbnail_ms` / `image_switch_ms` entries (there is no `memory_mb`
budget in v2; the former `open_folder_ms`/`zoom_frame_ms`/`ui_thread_ms` names
are gone). Lower-is-better for every latency/memory metric;
`cache_hit_ratio`, `cache_hit_rate`, `thumbnails_per_sec` and
`baseline_return_ok` are higher-is-better. A missing/invalid file falls back to
the in-code defaults + prints a `LOAD-FAILED` warning (fails open, never
silently passes).

### 2. Hard gate — the required Tier-1 `test` job (no separate workflow)

There is **no** `.github/workflows/perf-gate.yml`; only `ci.yml`, `nightly.yml`
and `release.yml` exist in `.github/workflows/`. The hard gate is the benchmark
CTest case itself:

- `bench_enforce` is registered in `src/CMakeLists.txt` and marked `RUN_SERIAL`.
- The Tier-1 `test` job of `.github/workflows/ci.yml` runs the whole CTest suite
  (`ctest --output-on-failure --output-junit test-results.xml -j$testJobs`), and
  `test` is one of the jobs the required `ci-gate` aggregator depends on — so a
  violated budget **fails the PR**. No `|| true` anywhere on that path.
- The nightly `quality` job adds the baseline trend run
  `mviewer_bench --enforce --regression --profile ci --budget
  benchmark/performance_budget.json`, whose ±10 % diff against
  `benchmark/perf_baseline.json` exits non-zero on a regression (nightly
  reporting; nightly never blocks a PR).

### 3. Local verification — `bench_enforce` ctest

`src/CMakeLists.txt` adds `add_test(NAME bench_enforce COMMAND mviewer_bench
--enforce --profile auto --budget ${CMAKE_SOURCE_DIR}/benchmark/performance_budget.json)`
plus `set_tests_properties(bench_enforce PROPERTIES RUN_SERIAL TRUE)`.
So `.\build.ps1 Test` itself cannot go green with a perf regression —
the gate is enforceable locally, not just in CI.

### 4. CPU-aware profiles and test parallelism

`mviewer_bench --profile auto` selects `low-core` on hosts with up to four
logical cores and otherwise selects `base`. Only CPU-sensitive latency and
thumbnail-throughput metrics are scaled; memory, cache-hit, event-loop, and
stability limits are invariant. The nightly baseline uses the explicit `ci`
profile and regression comparison skips mismatched profiles. `build.ps1` and
`ci.yml` derive CTest `-j` from logical core count, leaving one core available;
`bench_enforce` is `RUN_SERIAL`; `bench_smoke` remains a parallelizable link/run
smoke test.

## Acceptance criteria

| # | Criterion | Verification |
|---|-----------|--------------|
| A1 | `benchmark/performance_budget.json` exists with the 14 budgets (`schema_version: 2`) | `test -f` + JSON parse |
| A2 | `--enforce --budget` uses JSON limits, not hardcoded | code review + `bench_enforce` green |
| A3 | `bench_enforce` ctest FAILS the local suite on violation | run after injecting a bad budget → exit 1 |
| A4 | A violated budget fails a PR via the required Tier-1 `test` job (`ci-gate`) | CI run on a deliberately-slow commit (or dry assertion) |
| A5 | CI and local CTest use the CPU-aware profile and bounded parallelism | inspect `ci.yml`, `build.ps1`, and `src/CMakeLists.txt` |
| A6 | Full `.\build.ps1 Test` stays green (all 132 registered tests) | background run |
| A7 | Low-core profile adjusts only declared CPU-sensitive metrics | `--profile low-core` output + focused benchmark |
| A8 | Cross-profile baseline comparison is skipped with an explicit warning | `--profile low-core --regression` |

## Out of scope (per freeze + user "no big refactor")

- No change to `Benchmark`/`Scenario` math, `CacheManager`, `ImageRepository`,
  `Scheduler`, `Domain`, `Core` layering.
- GPU tile pipeline (M13.2) deferred per user's explicit "先不要碰 GPU".
- This milestone makes the **threshold gate** real (hard budgets from
  `performance_budget.json`). The baseline diff landed afterwards as well:
  `--enforce --regression` compares against the committed
  `benchmark/perf_baseline.json` (±10 %, `fail_on_regression: true`) and runs in
  the nightly `quality` job. What is still manual is *refreshing* that baseline —
  no script in the tree writes it.
