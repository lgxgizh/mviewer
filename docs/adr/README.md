# Architecture Decision Records (ADR) — Index

> This index is the **first entry point** for Agents and Reviewers. Any review, refactoring proposal, or architecture discussion must be checked against this index first: decisions recorded in existing ADRs must not be silently overturned. To overturn one, submit a new ADR that supersedes the old ADR.

## Core decisions (by topic)

### Image and data model

| ADR | Decision | One-line rationale |
|---|---|---|
| [002](002-why-image-data-not-qimage.md) | Core layer uses `ImageData`, not `QImage` | Core must be Qt-free and support >8-bit / multi-plane formats |
| [008](008-why-unified-image-frame.md) | A single `ImageFrame` runs through decode → cache → render | Eliminate cross-layer format conversion and copies |
| [023](023-const-image-view.md) | Read-only pixels go through `ConstImageView` / `constView()` | Remove const `view()`; a const image no longer hands out a writable pointer |

### Layering and dependencies

| ADR | Decision | One-line rationale |
|---|---|---|
| [001](001-why-qt-widgets.md) | UI uses Qt Widgets (not QML) | Mature, controllable, suited to professional desktop tools |
| [004](004-why-repository-pattern.md) | Repository is the single manager of image access | UI does not touch cache/decode details directly |
| [010](010-why-ui-widgets-lightweight.md) | UI widgets stay lightweight | Business logic sinks into Application/Core |
| [011](011-viewer-core-boundary.md) | Viewer/Core boundary is frozen | Prevent UI logic from leaking into the core layer |
| [014](014-ui-tu-split-by-responsibility.md) | Large UI files are split into TUs by responsibility | Hard constraints such as `mainwindow.cpp` < 1000 lines |
| [016](016-qt-boundary-in-core-headers.md) | core/domain headers must not include Qt (two named adapter headers excepted) | The rule must match the R5 gate and be auditable |
| [017](017-process-lifetime-services.md) | Process-lifetime services are intentionally not destroyed; object-lifetime destruction must hold; tests return from `main()` after shared shutdown | Distinguish "platform exit limits" from "forgot to destroy", and let stress tests guard the latter |
| [018](018-thumbnail-cpu-budget.md) | Thumbnail thread cap is half the core count, at low priority, and yields briefly during foreground decode/resample | Keep thumbnails from contending for CPU with current-image decode and compare hi-res resample |

### Cache and scheduling

| ADR | Decision | One-line rationale |
|---|---|---|
| [006](006-why-hierarchical-cache.md) | Tiered cache (memory / thumbnail / disk) | Different access patterns get different capacity policies |
| [021](021-compare-memory-current-pair-only.md) | Compare keeps only the on-screen pair in memory; leaving releases the full-image cache and returns the free heap | Compare pairs are always chosen manually; no prefetch or retention of the previous pair |
| [007](007-why-priority-scheduler.md) | Priority scheduler | Visible region > prefetch > background tasks |
| [022](022-scheduler-queue-metrics-and-drain.md) | `queue_depth` is tasks not yet started; `active_tasks` is tasks currently executing; drain uses a condition variable | Queue depth and in-flight tasks are no longer recorded as the same number |
| [024](024-mip-lod-replace-accounting.md) | Writing lod 0 drops that key's mip chain; replacing one mip level is accounted by the delta | A new full image must not leave old preview mips, and trim must not count the same level twice |

### Compare and analysis

|---|---|---|

| [013](013-p2-plugin-sdk-frozen.md) | Plugin SDK is frozen | ABI stability over flexibility |

## Governance rules (for Agent Review citation)

1. **UI must not reference Cache directly** (ADR-004/006) → `scripts/architecture_gate.ps1` R1
2. **Widgets must not access Repository directly** (ADR-004/010) → architecture_gate R2
3. **Compare must not depend on Thumbnail** (ADR-003/009) → architecture_gate R3
4. **Core/Domain headers are Qt-free** (ADR-002/011) → `scripts/audit_qt_boundary.ps1`
5. **UI large-file line-count cap** (ADR-014) → `scripts/complexity_gate.ps1`

PRs that violate the rules above: architecture_gate reports a Warning, and the Reviewer (Hermes) adjudicates against the corresponding ADR.

## How to add an ADR

1. Copy the template: increment the number (`015-...md`); filename `NNN-kebab-case-topic.md`
2. Required four sections: Context / Decision / Consequences / Status
3. When superseding an old decision: the new ADR marks `Supersedes: ADR-NNN`; the old ADR marks `Superseded by`
4. Update this index

The `legacy/` directory holds historical documents for archaeology only. It is not a basis for current decisions.
